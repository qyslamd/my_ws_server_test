## 2. "不丢失高性能"的验收口径

把性能拆三层,避免"感觉慢了"这种无法验收的争论。

| 编号 | 层级 | 目标 | 默认验收值 | 状态 |
|---|---|---|---|---|
| P1 | 数据完整性/吞吐 | 采集与传输不因 UI 而降级 | 单流 ≥ 20 MB/s,聚合不超过链路 60% | 🟡 |
| P2 | UI 响应/渲染 | 浏览器能跟上数据节奏 | 本机 p99 上屏 < 20 ms;LAN < 50 ms;60 fps 下 10 万点 | 🟡 |
| P3 | 稳定性 | 长时间运行不退化 | 连续 1 小时内存无增长,无 >50 ms 长任务 | 🟡 |
| P4 | 硬实时/抖动 | UI 不承担确定性 | 明确不作为目标;安全逻辑留在服务端 | ✅ |

> 说明:Qt/C# 直接调 DLL 是进程内路径,换成 WS 后多了一次序列化 + TCP + JS 解码。
> 在本机和局域网下,这部分通常在 1 ms 量级,相对 16.7 ms 的帧预算可忽略;
> 真正的瓶颈是渲染策略,不是传输。

## 3. 逐项确认

### 3.1 总体架构

| 编号 | 确认项 | 状态 | 说明 |
|---|---|---|---|
| A-01 | 控制/配置/查询走 **HTTP REST**,服务端主动推送走 **WS** | ✅ | 你提出"WS 最大的特点就是服务端推数据;HTTP 可以 RESTful" |
| A-02 | WS 上行只保留 **credit** 和协议级 Pong | 🟡 | 高频但极小,走 HTTP 会产生大量请求 |
| A-03 | **WS 连接是会话锚点**,HTTP 请求带 `X-Session-Id` | 🟡 | 一个存活判据,避免"HTTP 通但 WS 已死" |
| A-04 | 二进制帧 = **24 字节头 + TLV 块** | 🟡 | 比 v0 的 12 字节头多了 bodyLen 与帧级时间戳 |
| A-05 | 每个流用 **META(JSON)自描述**负载布局 | 🟡 | 底座不解释业务字段 |
| A-06 | 底座**零业务语义**,不认识任何总线 | ✅ | 你的核心定位 |
| A-07 | v1 **不引入 MQTT/broker** | 🟡 | 对比结论:多一个 broker、多一跳、联锁变间接 |
| A-08 | v1 **不引入 OPC UA 作为主协议** | 🟡 | 需要对外互操作时再加单向适配模块 |

### 3.2 会话与安全

| 编号 | 确认项 | 状态 | 说明 |
|---|---|---|---|
| C-01 | **1:1 单会话** | ✅ | 你的使用场景 |
| C-02 | WS 断开/心跳超时 = **SAFE_STOP** | ✅ | 你明确要求"保证安全结束任务" |
| C-03 | 心跳:服务端 5 s Ping,15 s 判死 | 🟡 | 浏览器自动回 Pong,客户端无需额外代码 |
| C-04 | 重连 = **新会话**,不续跑、不补发 | ✅ | 安全语义的直接推论 |
| C-05 | 同一时刻只允许一个活动会话 | ✅ | 1:1 |
| C-06 | 第二条 WS/第二个 sid 被拒绝 | 🟡 | 关闭码 4001;同 sid 重连替换旧连接 |
| C-07 | 显式 `stop` 后业务有限时间收尾(建议 ≤5 s) | 🟡 | 超时强制安全值 |
| C-08 | "安全值"由业务模块定义 | ✅ | 底座不解释 DA/DIO 的安全状态 |
| C-09 | 会话结束后 HTTP 返回 409 + 2001 | 🟡 | 避免操作已失效的会话 |

### 3.3 数据通道

| 编号 | 确认项 | 状态 | 说明 |
|---|---|---|---|
| D-01 | 流分三类:`sample` / `record` / `state` | 🟡 | 媒体类移出 v1 |
| D-02 | 默认**无损、保序**,seq 检测缺口 | ✅ | 你的数据"基本上都不能丢" |
| D-03 | 每流**有界环形缓冲**,溢出按整帧淘汰 | 🟡 | 采集线程永不阻塞 |
| D-04 | **credit 流控**只作用于 `sample`/`record` | 🟡 | `state` 可合并,流控无意义 |
| D-05 | `state` 只保留最新值,订阅时全量、之后增量 | 🟡 | 适合设备状态类数据 |
| D-06 | 溢出必须发 `core.overrun`,禁止静默丢 | 🟡 | 你要求可观测,不能"悄悄少了" |
| D-07 | `record` 统一容器 `[ts][len][payload]` | 🟡 | CAN/1553B/429 只需写 META 字段布局 |
| D-08 | 帧级时间戳 + 每条记录时间戳 + timebase 声明 | ✅ | 你确认"通常靠时间戳" |
| D-09 | **不做跨流时间对齐** | ✅ | 你明确"各干各的" |
| D-10 | 分片只允许 `AUX` 块,字节级拼接 | 🟡 | 简单、可复用 TLV 解析器 |
| D-11 | 订阅走 HTTP,**响应直接带完整 META** | 🟡 | 解决 `window:0` 时前端拿不到解析信息 |
| D-12 | `window:0` = 只注册、不推数据,之后 credit 放量 | 🟡 | 适合前端慢启动 |
| D-13 | 无人订阅时不产生投递义务 | 🟡 | 不占 seq、不报 overrun,避免撑爆缓冲 |
| D-14 | 单帧默认上限 8 MiB,单流缓冲 sample 4 / record 8 MiB | 🟡 | 工程基线,可用 limits 覆盖 |
